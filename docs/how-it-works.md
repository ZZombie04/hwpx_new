# 작동 원리

## 1. HWPX 구조

HWPX 는 ZIP 컨테이너입니다.

```
mimetype
Contents/header.xml     글자 모양(charPr) · 문단 모양(paraPr) · 테두리/배경(borderFill)
Contents/section0.xml   본문: 최상위 문단(hp:p) 목록. 표(hp:tbl)는 문단의 run 안에 들어 있음
Contents/content.hpf    패키지 목록/메타데이터
Preview/                미리보기 이미지·텍스트
```

## 2. 분석 (`analyze.py`, `styleprint.py`)

`section0.xml` 의 최상위 문단 하나를 **블록**으로 보고 역할을 붙입니다.

- **글머리**: 문단 앞머리의 기호(○ ㅇ - □ ※ ◦ ㆍ, 글머리 사용자 영역 글자, 자모 `ㅇ`)를 글자 종류로 판정. 문단 모양이 자동으로 기호를 붙이는 서식(글머리/개요)도 인식.
- **번호**: `1.` `가.` `1)` `가)` `(1)` `(가)` `①` `㉮` … **소제목**: 번호가 있고 큰 글자, 또는 `Ⅰ | 제목` 처럼 칸이 나뉜 표, 또는 1칸 표.
- **박스**(1×1 표), **표**(나머지), **사진/도형 문단**, **빈 줄**, **본문**.
- **표지 구간**: 문서 앞쪽에서 본문(글머리·번호·본문·자료 표)이 시작되기 전까지. 표지에서 가장 큰 글자의 칸이 제목 칸.
- **서식 종류(class)**: 글자 크기·색·굵기·글꼴, 문단 정렬·들여쓰기·줄간격·간격, 표의 칸 색·테두리가 **실제 값으로** 같은 블록끼리 묶어 `H1` `B2` `T3` 같은 이름을 붙입니다(스타일 번호가 달라도 모양이 같으면 같은 종류).

## 3. 서식 키트 (`builder.py` 의 `Kit`)

- **견본 고르기**: 표지를 뺀 본문에서 *가장 흔한* 모양의 블록을 견본으로(처음 나온 것이 아님).
  글머리는 (기호, 왼쪽 여백)으로 단계, 번호는 종류, 소제목은 번호 종류(Ⅰ./1./가./기호)로 나눠 글에 맞는 견본을 고릅니다.
- **간격**: 서식에서 '앞 역할 → 뒤 역할' 사이에 실제로 있던 빈 줄을 그대로 따릅니다(관찰한 적 없는 조합은 앞 역할 기준).
- **표**: 새 표와 열 수가 같으면 **같은 자리의 칸**(글자·문단·테두리·칸 색·줄 높이)을 그대로 복제하고 줄 수가 늘면 가운데 줄 모양으로 채웁니다.
  열 수가 다르면 머리/본문 × 첫/중간/끝 열 모양을 쓰고, **테두리는 '가장자리 모형'**(바깥 선 · 머리 아래 선 · 안쪽 가로/세로 선, 열별)으로 새 borderFill 을 만들어 줄 수가 달라도 선 모양이 유지됩니다.
  열 너비는 서식 표와 같은 열 수면 서식 비율을 씁니다.
- **글자 구성**: 서식 문단이 '굵은 앞말 + 보통 글'처럼 여러 글자 덩어리였으면 쌍점·기호 위치에서 나눠 같은 구성을 따릅니다. `**굵게**` 는 굵은 글자 모양(없으면 새로 만듦)으로.
- **글 바꾸기(like/clone)**: 글자 단위 비교로 바뀐 낱말만 새로 쓰고 나머지 글자 모양은 그대로 둡니다.

## 4. 조립과 뼈대 Markdown (`reflow.py`, `mdparse.py`)

서식의 블록을 글 내용으로 되돌려 **뼈대 Markdown** 을 만듭니다(기본 선택과 다른 모양의 블록에만 `{종류}` 표시). 사진·도면·양식(격자형/병합 표)은 `@clone`/`paras` 로 통째로 복제하고,
색이 섞인 문단은 `@like` 로 글자 모양을 빌립니다. AI 는 이 뼈대를 고쳐 쓰고, `build` 는 Markdown → 블록 → 서식 요소 **깊은 복사** → 글 교체 → 새 `section0.xml` 순으로 조립합니다.
`hwpx-new selfcheck` 는 이 뼈대를 그대로 다시 조립해 원본과 블록별 모양(`styleprint.py`의 지문)을 비교합니다.

## 4-1. 사진

`images.py` 가 사진을 읽어 EXIF 방향을 바로잡고 긴 변 1600px 로 줄이며 HEIC/WEBP 를 JPG/PNG 로 바꿉니다. 한글이 만든 파일과 같은 구조로 `BinData/imageN.*` 에 저장하고 `content.hpf` 매니페스트에 등록한 뒤, `<hp:pic>`(글자처럼 취급)을 문단 또는 표 셀 안에 넣습니다.

## 5. PDF 와 조판 점검

변환 엔진 우선순위: **한글(COM 자동화, `hancom.py`)** → **LibreOffice** → **내장 렌더러**(HWPX→HTML→Chrome/Edge 인쇄, 없으면 pymupdf).

한글 자동화: 한글이 띄우는 "파일 접근 허용" 창은 **이 도구가 띄운 한글 프로세스의 작은 창**에서 **작업 폴더 안 파일 요청일 때만** [접근 허용]을 눌러 넘깁니다. 문서가 실제로 열렸는지는 쪽 수·글자 수로 확인합니다(`Open` 반환값은 믿지 않음).
승인 창이 닫히지 않으면(화면보호기·잠금) 50초 뒤 중단하고 이 도구가 띄운 한글만 정리한 뒤 다음 엔진으로 넘어갑니다.

`qa.py` 는 PDF 에서 각 블록의 글자 위치를 찾아 빈 쪽 · 소제목 고립 · 표 잘림 · 마지막 쪽 토막을 판정하고, `pipeline.py` 가 쪽 나눔·간격 압축으로 자동 보정(최대 6회)해 점수가 가장 낮은 시도를 최종본으로 고릅니다.
빌드는 날짜-요일 불일치, 표 칸 수, **서식 원문 문장 잔재**, 구조 검증(`validate.py`)도 경고합니다.

## 6. 안전

- 원본 서식은 절대 수정하지 않습니다(복사본에서 작업).
- 한글 자동화는 **이 도구가 띄운 한글 프로세스만** 정리합니다. 사용자가 열어 둔 한글 창은 건드리지 않습니다.
- 다른 도구가 서식 파일에 남긴 '만든 프로그램' 표시(`content.hpf` 메타데이터)는 결과 문서에 옮기지 않습니다.
