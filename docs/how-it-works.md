# 작동 원리

## 1. HWPX 구조

HWPX 는 ZIP 컨테이너입니다.

```
mimetype
Contents/header.xml     글자 모양(charPr) · 문단 모양(paraPr) · 테두리/배경(borderFill)
Contents/section0.xml   본문: 최상위 문단(hp:p) 목록. 표(hp:tbl)는 문단의 run 안에 들어 있음
Contents/content.hpf    패키지 목록/메타데이터
Preview/                미리보기 이미지·텍스트
```

## 2. 분석: 블록에 역할 붙이기 (`analyze.py`)

`section0.xml` 의 최상위 문단 하나를 **블록**으로 보고 역할을 붙입니다.

1. 표가 있는 문단: 1열·2행 이하 + 짧은 글 → **소제목(표형)**, 1×1 → **박스**, 그 외 → **표**
2. 표가 없는 문단: 빈 문단 → **빈 줄**, `●○-` 또는 글머리 기호 글자 → **글머리**, `1.` `가.` `1)` → **번호**
3. 앞쪽 블록 중 번호 머리말이 아닌 큰 글씨 → **표지/제목**, 그 아래 짧은 우측 정렬 → **부제**

`header.xml` 을 함께 읽어 글자 크기·굵기, 문단 정렬·들여쓰기, 셀 배경색을 판단 근거로 씁니다.

## 3. 서식 키트 (`builder.py` 의 `Kit`)

- **표**: 머리글 행(배경색 셀) / 본문 행 / 마지막 행, 첫 열 / 중간 열 / 마지막 열 조합마다 테두리(borderFill)·문단·글자 서식을 학습.
  서식에 없는 조합은 가장 가까운 조합으로 대체. 가운데/왼쪽 정렬용 문단 모양이 없으면 `header.xml` 에 변형을 추가.
- **글머리**: 기호 글자와 왼쪽 여백으로 단계를 구분. 서식에 없는 하위 단계는 들여쓰기 변형 + `-` 기호.
- **번호**: `1.` `가.` `1)` `가)` `(1)` `①` 종류별 문단 서식.
- **간격**: 각 역할 뒤에 어떤 빈 문단이 오는지 관찰해 가장 흔한 것을 자동 삽입(소제목 앞은 넉넉히).

## 4. 조립

블록 명세 → 서식 요소를 **깊은 복사** → 글만 교체 → 새 `section0.xml`. 표는 셀마다 원본 셀을 복제하고 문단을 새로 채우며,
글자 수·열 너비로 행 높이를 추정합니다(한글이 열 때 필요하면 다시 늘림). 좁은 열은 넓은 열에서 폭을 덜어 옵니다.

## 4-1. 사진

`images.py` 가 사진을 읽어 EXIF 방향을 바로잡고 긴 변 1600px 로 줄이며 HEIC/WEBP 를 JPG/PNG 로 바꿉니다. 한글이 만든 파일과 같은 구조로 `BinData/imageN.*` 에 저장하고 `content.hpf` 매니페스트에 등록한 뒤, `<hp:pic>`(글자처럼 취급) 을 문단 또는 표 셀 안에 넣습니다. 사진 대지는 서식의 표 서식을 그대로 쓰는 표입니다.

## 5. PDF 와 조판 점검

변환 엔진 우선순위: **한글(COM 자동화)** → **LibreOffice** → **내장 렌더러**(HWPX→HTML→Chrome/Edge 인쇄, 없으면 pymupdf).

`qa.py` 는 PDF 에서 각 블록의 글자 위치를 찾아 다음을 판정합니다.

| 문제 | 판정 | 자동 보정 |
|---|---|---|
| 빈 쪽 | 본문이 없는 쪽 | 자동 쪽 나눔 해제 → 간격 압축 |
| 소제목 고립 | 소제목과 다음 블록이 다른 쪽 | 소제목 앞 쪽 나눔 |
| 표 잘림 | 표 첫 행·끝 행이 다른 쪽 | 표 앞 쪽 나눔 |
| 마지막 쪽 토막 | 마지막 쪽 본문 3줄 이하 | 간격 압축(1→2단계) |

점수(문제 가중치 합)가 가장 낮은 시도를 최종본으로 고릅니다.

- 원본 서식은 절대 수정하지 않습니다(복사본에서 작업).
